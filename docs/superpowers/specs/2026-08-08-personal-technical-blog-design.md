# 个人技术博客设计

日期：2026-08-08

## 1. 目标

从零搭建一个公开可访问的个人博客，用于发布技术文章和学习笔记。作者在本地使用 Markdown 写作，GitHub 保存源码和文章，提交后自动完成校验、构建与发布。

首版先通过 GitHub Pages 上线，不等待域名和备案。后续在阿里云购买域名并完成 ICP 备案，再将同一份静态构建产物部署到中国内地的阿里云 OSS。迁移托管平台时不改变文章格式和目录结构。

## 2. 已确认的约束

- 使用 Astro 构建纯静态网站。
- 面向中国大陆读者，长期正式托管目标为阿里云 OSS。
- 作者在电脑上写 Markdown，不建设网页编辑后台。
- 首页以纯文字文章列表为核心，不使用文章封面图。
- 视觉语言参考 Compose 博客模板的配色、字体关系、留白和编辑杂志感，但不复制其代码、图片或页面结构。
- 首版不使用服务器、数据库、登录、评论或邮件订阅后台。
- 首版支持文章搜索、标签、代码高亮、目录、RSS、站点地图、深色模式和响应式布局。
- GitHub Pages 是备案期间的临时公开入口；自定义域名不是首版上线的阻塞条件。

## 3. 系统架构

发布链路如下：

```text
本地 Markdown
      ↓
Astro 内容校验与静态构建
      ↓
GitHub 公开仓库
      ↓
GitHub Actions
      ├─ 第一阶段：GitHub Pages
      └─ 备案完成后：阿里云 OSS + 自定义域名 + HTTPS
```

系统划分为五个边界清晰的部分：

1. **内容层**：Markdown 正文、文章元数据和与文章同目录的本地附件。
2. **内容查询层**：Astro Content Collections 负责结构校验、草稿过滤、排序、标签聚合和相关文章查询。
3. **展示层**：页面布局与可复用组件负责文章列表、文章正文、搜索、标签和主题切换。
4. **构建质量层**：类型检查、静态构建、内部链接检查和产物检查在 CI 中运行。
5. **发布层**：GitHub Actions 将同一静态产物发布到当前目标，不让托管平台逻辑进入文章或页面组件。

网站没有运行时后端。搜索使用 Pagefind 的中文扩展构建产物，RSS、站点地图、阅读时间和标签页面也均在构建阶段生成。搜索界面独立实现以匹配博客视觉，索引文件与网站一起托管，不调用外部搜索服务。

## 4. 页面与信息架构

### 4.1 首页 `/`

首页同时承担文章归档职责，不再建设重复的“全部文章”页面，包含：

- 极简顶部导航：站点名称、首页、标签、关于、搜索和主题切换。
- 柔和粉色、黄色、淡紫色渐变的个人介绍区。
- 标签筛选与静态全文搜索入口。
- 按发布日期倒序排列的纯文字文章列表。
- 文章归档生成 `/page/2/` 形式的静态分页；界面可将下一页链接呈现为“加载更多”，确保无 JavaScript 时仍可浏览。

每条文章记录显示分类标签、标题、简短摘要、发布日期、更新时间（存在时）和预计阅读时间。列表使用细分隔线；悬停时仅增加淡色背景、文字位移和箭头反馈。

### 4.2 文章页 `/posts/:slug/`

文章页不显示封面图，结构为：

- 分类与主题标签。
- 大号衬线标题。
- 摘要、发布日期、更新时间和阅读时间。
- 桌面端可见的文章目录；窄屏使用可折叠目录。
- Markdown 正文、代码高亮、代码复制按钮、引用块、表格和脚注样式。
- 上一篇、下一篇与同标签相关文章。

正文最大宽度为 720px，保持长文阅读舒适。标题锚点可直接复制，用于分享具体章节。

### 4.3 标签页 `/tags/` 与 `/tags/:tag/`

标签首页展示全部标签及文章数量；标签详情页复用首页的纯文字列表。`article` 和 `note` 是内容类型，React、TypeScript、工程化等是主题标签，两者不混用。

### 4.4 关于页 `/about/`

展示个人简介、关注方向、GitHub 等公开联系方式和 RSS 入口。首版不放联系表单，避免引入后端和垃圾信息处理。

### 4.5 基础页面

- 自定义 404 页面提供返回首页与搜索入口。
- RSS 输出全部已发布文章。
- XML 站点地图与 `robots.txt` 在构建时生成。

## 5. 内容模型

每篇文章使用一个独立目录，正文和本地附件放在一起。首版虽然不显示封面图，但允许正文内部使用图片，目录结构无需为此改变。

```text
src/content/posts/
└── react-state-update/
    ├── index.md
    └── diagram.svg
```

元数据结构如下：

```yaml
---
title: React 状态更新机制
description: 梳理 React 状态更新的基本原理
publishedAt: 2026-08-08
updatedAt: 2026-08-10
type: article
tags:
  - React
  - 前端
draft: false
---
```

字段规则：

- `title`、`description`、`publishedAt`、`type`、`tags` 和 `draft` 必填。
- `updatedAt` 可选，但不得早于 `publishedAt`。
- `type` 只能为 `article` 或 `note`。
- `tags` 至少包含一个主题标签，同一篇文章内不得重复。
- `publishedAt` 晚于构建日期的文章按预约内容处理，与草稿一样不进入生产产物。
- 目录名就是稳定 URL slug；发布后修改目录名视为 URL 迁移，必须增加重定向。
- `draft: true` 的内容可本地预览，但不会进入生产页面、搜索索引、RSS 或站点地图。

## 6. 视觉设计

### 6.1 设计语言

视觉方向来自 [Compose 模板公开预览](https://compose-template.framer.website/)的编辑杂志感：柔和色彩、大量留白、大号衬线标题、简洁无衬线界面文字、圆角容器和克制动效。实现将独立编写，不使用模板原始代码与素材。

首版色彩令牌：

- 页面背景：`#FFFFFF`
- 主文字：`#18202B`
- 次要文字：`#727A87`
- 边框：`#E9E9E7`
- 中性表面：`#F7F7F5`
- 柔粉：`#FFE5E7`
- 柔黄：`#FFF0B8`
- 淡紫：`#F2E5F7`
- 淡绿：`#E8F5E9`

介绍区使用柔粉、柔黄和淡紫的低对比渐变。分类标签从上述柔和色中稳定映射，同一标签在全站保持同色。深色模式使用同色相的低亮度版本，文字对比度满足 WCAG AA。

### 6.2 字体与排版

- 展示标题：`Georgia, "Songti SC", "Noto Serif CJK SC", "Source Han Serif SC", STSong, serif`。
- 正文与界面：`ui-sans-serif, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。
- 代码：`ui-monospace, "SFMono-Regular", Consolas, "Liberation Mono", monospace`。

字体全部采用本地系统字体栈，不依赖境外字体服务。桌面端页面内容最大宽度为 1120px，文章正文最大宽度为 720px。列表标题使用衬线字体，元数据和控件使用无衬线字体。

### 6.3 组件外观

- 容器圆角以 16px 为主，标签使用胶囊形圆角。
- 不使用常驻投影，通过边框、留白和背景色建立层级。
- 动画控制在 150–250ms，只用于悬停、主题切换和移动菜单。
- 遵循 `prefers-reduced-motion`，用户要求减少动态效果时关闭位移与渐变动画。
- 移动端文章列表保持单列，导航折叠为简洁菜单，任何内容不依赖横向滚动。

## 7. 写作与发布流程

日常流程为：

```text
创建文章目录和 index.md
      ↓
本地预览
      ↓
运行内容与构建检查
      ↓
提交并推送 GitHub
      ↓
GitHub Actions 自动发布
```

本地开发命令负责实时预览。生产构建会统一校验文章元数据、类型、路由、链接和输出产物。作者不需要手工上传 HTML 或登录托管控制台发布文章。

## 8. 部署与域名演进

### 8.1 第一阶段：GitHub Pages

- 初始化 Git 仓库并创建公开 GitHub 仓库。
- 远端仓库名称采用已认证 GitHub 账户名加 `.github.io`，获得账户根域名形式的 Pages 地址。
- 推送默认分支后，GitHub Actions 执行检查、构建和 Pages 部署。
- GitHub Pages 地址作为备案期间的临时公开入口。

### 8.2 第二阶段：域名与备案

- 博客上线后在阿里云选择可注册的个人域名并完成实名认证。
- 申请 ICP 备案期间不改变 GitHub Pages 发布流程。
- 自定义域名不是首版验收项，域名文字选择也不影响代码设计。

### 8.3 第三阶段：阿里云 OSS

- 在中国内地地域创建专用 OSS Bucket，仅存放生成后的公开静态资源。
- 完成备案后绑定自定义域名、配置 DNS 和 HTTPS。
- GitHub Actions 使用加密变量保存最小权限的阿里云凭据，并将构建目录同步至 OSS。
- 发布采用“先构建并验证、后同步”的顺序；构建失败不会覆盖线上旧版本。
- 通过内容哈希为静态资源设置长期缓存，HTML 使用短缓存，确保新文章及时可见。
- 暂不启用 CDN；只有实际访问监测证明 OSS 直连不足时再增加。
- GitHub Pages 可保留为故障备用地址，但正式页面设置自定义域名为 canonical，避免重复收录。

## 9. 错误处理与安全

- 内容元数据不符合 schema 时构建失败，并指出文件和字段。
- 内部链接、路由或静态资源缺失时 CI 失败，不执行部署。
- 草稿和未来发布日期文章不会进入生产产物。
- 部署失败时保留上一版可用网站，并在 GitHub Actions 中输出失败阶段。
- 阿里云访问密钥不进入仓库、日志或前端产物；部署账号只拥有目标 Bucket 所需的最小权限。
- OSS Bucket 只包含可公开下载的构建结果，私人资料使用不同 Bucket，且不与博客部署凭据共享权限。
- 所有公开入口强制 HTTPS，外部链接使用安全属性，用户输入仅存在于本地搜索框，不发送到服务端。

## 10. 验证策略

### 10.1 自动检查

- Astro 类型与内容 schema 检查。
- 生产静态构建。
- 生成页面、RSS、站点地图和搜索索引的存在性检查。
- 站内链接与静态资源链接检查。
- HTML 基础可访问性检查，包括标题层级、图片替代文本和表单标签。
- 对关键页面执行桌面与移动视口的渲染烟雾测试。

### 10.2 首版验收标准

1. 首页可展示无图片的文章列表，并可按标签筛选和搜索。
2. 技术文章和学习笔记使用相同 Markdown 流程，通过类型标签区分。
3. 文章页具备目录、代码高亮、复制按钮、阅读时间和前后文章导航。
4. 浅色与深色主题可切换并记住选择，移动端无横向溢出。
5. 推送一篇非草稿文章后，GitHub Actions 自动发布并可通过 Pages 地址访问。
6. 提交无效元数据或损坏链接时，CI 阻止部署且线上旧版本仍可访问。
7. RSS、站点地图、404 页面和 canonical 元数据均正确生成。
8. 网站不请求境外字体服务，也不依赖运行时数据库或服务器。

## 11. 首版范围外

- 评论、登录、点赞和用户系统。
- 网页 CMS 或在线编辑器。
- 邮件订阅与营销自动化。
- 访问统计和行为追踪。
- 多作者、付费内容和全文国际化。
- 阿里云 CDN、函数计算或长期运行的云服务器。

这些能力只有在博客实际使用产生明确需求后再单独设计，不为潜在需求提前增加复杂度。
